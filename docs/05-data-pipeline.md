# Пайплайн данных

**Пайплайн — это и есть продукт.** Код каталога тривиален; ценность — в проверенных данных. Все скрипты лежат в `backend/app/ingest/`, запускаются руками или кроном GitHub Actions (`.github/workflows/pipeline-cron.yml`; бонус — регулярное подключение не даёт Supabase free заснуть).

Каждый импортёр обязан писать `data_source`, `source_url`, `last_verified_at`.

## Фаза A — автоматический сид (недели 1–2) ✅ реализовано

| Скрипт | Что делает |
|---|---|
| `seed_sample.py` | 10 демо-вузов для разработки UI. `data_source='sample'`, цифры НЕ проверены — перед реальным запуском заменяются курацией |
| `seed_hipolabs.py` | скелет ~450 вузов целевых стран (имя/страна/домен) из Hipolabs API. Всё `is_published=false` — это заготовки, не публикуемые данные |
| `import_scorecard.py` | обогащение US-вузов из College Scorecard API: SAT p25/p75, tuition. Upsert по `external_ids.scorecard_id`. Ключ бесплатный (api.data.gov), `DEMO_KEY` хватает для проб |
| `update_fx.py` | курсы валют с open.er-api.com → таблица `currency_rates` → пересчёт `amount_usd` во всех costs. Еженедельно кроном |

Фаза 1.5: импорт UK из Discover Uni / HESA CSV (CC BY 4.0 — **атрибуция в футере обязательна**).

## Фаза B — ручная курация (недели 2–8 и навсегда) ✅ импортёр реализован

Источник истины — **один мастер Google Sheet**:
- вкладки зеркалят таблицы, дропдауны-валидация для enum-полей;
- каждая вкладка публикуется как CSV (Файл → Публиковать в интернете → CSV) → URL'ы в `SHEET_CSV_URLS`;
- `import_sheet.py` тянет CSV, валидирует каждую строку **Pydantic-моделью** (`UniversityRow`), делает upsert.

Правила импортёра:
- невалидная строка отклоняется **громко** (в отчёт с номером строки и причиной), никогда молча;
- импортёр **выигрывает конфликты** у ручных правок в БД — Sheet первичен;
- быстрые правки можно делать в table editor Supabase, но следующий импорт их перезапишет.

Процесс курации (детали в [curation_guide_ru.md](curation_guide_ru.md)):
1. открыть официальную страницу international admissions;
2. заполнить строку, проставить `source_url` + `last_verified_at`;
3. `is_published=TRUE` только после проверки всех ключевых полей.

Экономика: один вуз ≈ 20–30 мин → 100 вузов ≈ 40–50 часов ≈ 4–6 недель параллельно с учёбой при норме **20 вузов/неделю фиксированными батчами** (не «пока не устану» — защита от выгорания). Курация параллелится: 2–3 друга-куратора с колонкой `curated_by`, код — нет.

Кастомную админку в v1 **не строить** — Sheet + Supabase table editor закрывают всё.

## Фаза C — парсеры (фаза 2+, с юридической осторожностью)

Только когда каталог > 300 вузов и обновление руками станет узким местом:
- только сайты, чьи robots.txt/ToS позволяют; жёсткий rate-limit (1 req/2 сек);
- парсить **факты** (дедлайны, сборы — факты не защищены копирайтом), не тексты (защищены);
- **никогда** не парсить QS/THE/UniPage/Studyportals — лицензии и ToS;
- парсер пишет **предложения** в очередь на ревью (таблица `staging_changes`), никогда напрямую в опубликованные строки;
- хранить URL источника на каждый факт.

При 300 вузах ручная курация дешевле поддержки парсеров — не спешить с этой фазой.

## Свежесть как фича продукта

- На каждой карточке и детальной странице: «Проверено: 12.07.2026 · Источник ↗».
- `freshness_report.py` (TODO фаза 2): строки с `last_verified_at` старше 120 дней = to-do лист курации.
- Ежегодный «спринт обновления» в мае–июле — перед сезоном подачи, когда вузы публикуют новые цифры.
- Кнопка «Сообщить об ошибке» на каждой странице — пользователи становятся бесплатным QA.
- Приоритет перепроверки — топ-50 вузов по просмотрам.

Честно-устаревшее («проверено 200 дней назад») лучше скрыто-устаревшего. Сама прозрачность — дифференциатор против агентств и агрегаторов.
