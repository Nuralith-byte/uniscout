# Роадмап

Жёсткие фазовые рамки — главная защита от выгорания соло-разработчика. Правило: **сначала каталог на 100 вузов, потом любая фича фазы 2.**

## Фаза 1 — MVP (недели 1–8)

### Недели 1–2: фундамент + деплой ✅ (скелет готов)
- [x] Монорепо: `frontend/`, `backend/`, `app/ingest/`, `docs/`
- [x] Схема БД + Alembic (initial migration)
- [x] Сид-скрипты (sample, Hipolabs, Scorecard, FX)
- [ ] **Задеплоить hello-world end-to-end: Vercel + Render + Supabase.** Деплой ПЕРВЫМ делом, не последним — сюрпризы free tier дешевле всего ловить рано; публичный URL к неделе 2 = мотивация

### Недели 3–4: каталог ✅ (скелет готов)
- [x] Поиск/фильтры (страна, «мой SAT», «мой IELTS», бюджет, сортировки)
- [x] Страница каталога + детальная страница (русский UI)
- [x] Кириллический поиск по алиасам
- [x] Избранное в localStorage
- [ ] Google Sheet шаблон + первый реальный импорт
- [ ] Старт курации: 20 вузов/неделю

### Недели 5–6: аккаунты
- [ ] Supabase Auth на фронте (email + Google)
- [ ] Серверное избранное + мёрдж localStorage при первом логине (эндпоинт готов)
- [ ] Профиль с баллами → предзаполнение фильтров «мои шансы»
- Избранное — единственная фича за логином, намеренно: гейт меряет реальный интент

### Недели 7–8: данные + запуск
- [ ] Докурировать до **100 вузов**: США ~40 / UK ~15 / ЕС ~10 / Корея+Япония+Китай+Гонконг ~20 / Турция ~15
- [ ] Бейджи «проверено N дней назад» (готово в UI), кнопка «сообщить об ошибке»
- [ ] Подключить аналитику (PostHog/Umami)
- [ ] **Софт-запуск:** одноклассники брата → правки по фидбеку → казахстанские студенческие Telegram-чаты

**Метрика успеха MVP:** 10 реальных абитуриентов говорят «сэкономило мне часы»; измеряется кликами по apply-ссылкам и избранным-за-сессию.

### Явно ВНЕ фазы 1
Таблица programs с данными, казахский/английский UI, сравнение вузов, напоминания, кастомная админка, парсеры, SSR/SEO, мобильное приложение (никогда — responsive web).

## Фаза 2 (месяцы 3–5)

- **Калькулятор шансов** — rule-based светофор: зелёный/жёлтый/красный против диапазона SAT p25–p75. Прозрачно и объяснимо, никакого ML.
- **Сравнение 2–4 вузов** бок о бок — клиентское, поверх существующего API.
- **Email-напоминания о дедлайнах** для избранного: GitHub Actions cron + Resend free tier (100 писем/день).
- **Казахский язык** (колонки `_kk` + переключатель).
- **SEO:** пререндер ~300 детальных страниц на билде.
- Каталог до **300 вузов**; `freshness_report.py`; кнопка «сообщить об ошибке» → очередь модерации.

## Фаза 3 (месяцы 6+)

- **Трекер заявок:** статусы и чеклисты по каждому вузу из избранного («эссе — черновик», «рекомендации — запрошены»).
- **Отзывы поступивших казахстанцев** — защищаемый контент-moat, которого нет ни у кого.
- **Монетизация** (см. [08-business.md](08-business.md)): лид-ген test-prep → freemium → спонсорские профили.
- Только здесь оправдан бюджет >$0 на инфраструктуру.

## Анти-цели (чтобы не расползтись)

- Не агентство: не «сопровождаем» и не гарантируем поступление.
- Не для потока в Россию — другой процесс, другая боль.
- Не мобильное приложение — responsive web покрывает всё.
- Не глобальный агрегатор «всех вузов мира из API» — это путь к пустым полям как у Studyportals.
