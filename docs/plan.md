# План: платформа поиска зарубежных университетов для абитуриентов из Казахстана

## Контекст

Первокурсник CS (братишка пользователя) хочет построить пет-проект с потенциалом стартапа: сайт, где абитуриенты из Казахстана находят зарубежные университеты со всей информацией в одном месте — требования (SAT, IELTS/TOEFL, внеклассная активность), стоимость подачи и обучения, дедлайны, прямые ссылки на официальные порталы подачи. Фичи: поиск с фильтрами «мои баллы + мой бюджет», избранное. Цель — сократить поиск информации с часов/дней до минут.

Ограничения: соло-разработчик (1 курс), бюджет $0 (только бесплатные тарифы), стек из знакомого: Python, TypeScript, React, Vite, PostgreSQL (+Redis/MongoDB — отбрасываем, см. ниже). Данные: открытые API + парсинг + ручная курация. География: топ-вузы разных регионов, популярные у казахстанцев (США, UK/Европа, Корея/Китай/Япония/Турция).

## 1. Исследование рынка: ниша реально свободна

- **UniPage** (лидер СНГ) — платное агентство с тонким бесплатным каталогом-приманкой (полное сопровождение ~100 000 ₽). Нет фильтра «мой SAT/IELTS/бюджет», нет дедлайнов, данные устаревшие.
- **Studyportals** (Bachelors/Mastersportal) — 270k+ программ, но только англоязычные программы и интерфейс, слабо по требованиям/стоимости, нет контекста КЗ.
- **Niche.com** — только США и для американцев (нет IELTS, виз, международных сборов).
- **Казахстанские агентства** (Nova Education, Impact Admissions, SmarTestPrep и др.) берут **108 тыс. – 1 млн KZT** за информационное посредничество — это прямое доказательство спроса. Их бизнес = информационная асимметрия; открытый каталог её разрушает.

**Вывод:** никто не даёт бесплатный структурированный русско/казахоязычный мульти-страновой каталог с персональной фильтрацией по своим баллам + дедлайнами + избранным. **Полезно ли в Казахстане — да:** ~90 тыс. казахстанцев учатся за рубежом (9-е место в мире), ~80% за свой счёт, ~160–250 тыс. выпускников школ в год. Целевая аудитория — не Россия-ориентированное большинство, а платящий сегмент США/UK/Европа/Азия (именно они платят агентствам $250–2300). Корея — самое быстрорастущее и хуже всего покрытое направление.

### Источники данных
| Источник | Что даёт | Лицензия |
|---|---|---|
| College Scorecard API (США) | tuition, SAT-диапазоны p25/p75, admission rate | бесплатно, public domain |
| IPEDS CSV (США) | глубина по 7000+ вузов | бесплатно |
| HESA / Discover Uni (UK) | данные по вузам UK | CC BY 4.0 (коммерческое ОК, с атрибуцией) |
| Hipolabs API | ~9700 вузов мира: имя, страна, домен | бесплатно (только справочник имён) |
| QS/THE рейтинги | рейтинги | **НЕ бесплатно коммерчески** — хранить только номер + ссылку наружу |

**Ключевая правда:** самые ценные поля (дедлайны, IELTS-минимумы, сборы за подачу, ссылки на порталы подачи) не существуют ни в одном бесплатном структурированном источнике → ручная курация ~100–300 вузов = основная работа и одновременно конкурентное преимущество (moat). Данные — это и есть продукт.

## 2. Архитектура: модульный монолит (твёрдая рекомендация)

**Один FastAPI-бэкенд с чётко разделёнными внутренними модулями. Никаких микросервисов.**

Почему микросервисы сейчас — ошибка: команда из 1 человека (нечего декаплить), $0 бюджет (бесплатные тарифы дают ОДИН веб-процесс; «сплит» = два холодно стартующих бесплатных дино, говорящих по HTTP без причины), вся БД < 50 МБ, 80% времени ушло бы на инфраструктуру вместо продукта. Путь миграции при росте: модуль `ingest/` → отдельный cron-воркер, поиск → отдельный сервис. Оба уже изолированы как модули, поэтому вынос — copy-paste, не переписывание. До ~100k MAU больше не понадобится.

```
backend/
  app/
    main.py               # FastAPI app factory
    core/                 # config, db session, security
    modules/
      catalog/            # вузы, программы, требования, стоимость, дедлайны
        router.py / service.py / models.py / schemas.py
      users/              # auth, профиль (баллы, бюджет)
      favorites/          # избранное CRUD
      admin/              # эндпоинты курации / импорта
    ingest/               # скрипты пайплайна данных (запуск руками/кроном, НЕ часть веб-приложения)
      seed_hipolabs.py
      import_scorecard.py
      import_sheet.py
frontend/                 # React + TS + Vite
```

Правило модульности: модули не импортируют чужие `models.py` напрямую — только через `service.py` соседа.

## 3. Стек (финальный выбор)

**Оставляем:** Python 3.12 + FastAPI + SQLAlchemy 2.0 + Alembic + Pydantic v2; PostgreSQL 16; React 18 + TypeScript + Vite + Tailwind.
**Выбрасываем MongoDB** — нет документо-образных данных, JSONB в Postgres покрывает гибкие поля, вторая БД удваивает ops-нагрузку без пользы. **Откладываем Redis** — кэшировать нечего на старте; добавить только при измеренном узком месте.

| Слой | Выбор | Почему |
|---|---|---|
| Backend | FastAPI + SQLAlchemy 2.0 + Alembic | авто-OpenAPI-доки на `/docs` (отлично для обучения), лучшая документация в современном Python. Django-админка соблазнительна, но её заменяет table editor Supabase |
| БД + Auth + админка | **Supabase free tier** (Postgres 500 МБ + Auth до 50k MAU + table editor) | один провайдер закрывает три задачи; 300 вузов ≈ <50 МБ — годы запаса. ⚠️ free-проект засыпает после ~7 дней неактивности — еженедельный cron пайплайна (GitHub Actions) заодно служит keep-alive. Fallback: Neon |
| Frontend | React+TS+Vite на **Vercel** (или Cloudflare Pages) | без холодного старта, глобальный CDN; SPA достаточно для MVP, Next.js/SSR НЕ добавлять сейчас (SEO — фаза 3, либо пререндер ~300 страниц на билде) |
| Поиск | Postgres FTS + pg_trgm | см. §7 |
| Auth-механика | **Supabase Auth**: фронт логинится через `@supabase/supabase-js` (email + Google OAuth, сброс пароля из коробки), бэкенд только проверяет JWT (FastAPI dependency, ~30 строк) | не писать свой JWT/reset-flow — именно там новички ошибаются. Учебное упражнение: сделать свой JWT по туториалу FastAPI в отдельной ветке, понять, что делает Supabase — и задеплоить Supabase |
| Хостинг API | **Render** free tier | ⚠️ холодный старт 30–60 сек после 15 мин простоя; митигации: UptimeRobot-пинг днём по КЗ + дружелюбный «будим сервер…» на фронте. Railway free — разовый кредит $5, кончится. Fallback: Fly.io |
| Аналитика | PostHog Cloud free (1 млн событий/мес) или Umami | + своя таблица `outbound_clicks` в Postgres — критичные для монетизации данные храним у себя |

Учебные материалы: официальный туториал FastAPI, fullstackopen.com для React. В неделю 1 отдельно изучить: Alembic-миграции и Pydantic-схемы.

## 4. Модель данных (PostgreSQL)

Главный принцип из анализа конкурентов: устаревшие данные убили доверие ко всем инкумбентам → **каждая таблица с фактами несёт `data_source` + `last_verified_at`**, в UI бейдж «проверено N дней назад».

```sql
universities (
  id, slug UNIQUE, name_en, name_ru, country_code CHAR(2), city,
  website_url, apply_url,             -- прямая ссылка на портал подачи (главное поле!)
  application_system TEXT,            -- 'common_app' | 'ucas' | 'direct' | ...
  logo_url, description_ru,
  rankings JSONB,                     -- {"qs": 145} — только номер + ссылка наружу (лицензия)
  is_published BOOLEAN DEFAULT false, -- workflow курации: черновик → опубликован
  data_source TEXT, last_verified_at TIMESTAMPTZ, created_at, updated_at
)
programs (        -- в MVP опциональна: только для исключений/флагманских программ
  id, university_id FK, degree_level degree_level,   -- ENUM: bachelor|master|phd|foundation
  name_ru, name_en, field_of_study, url
)
admission_requirements (
  -- Компромисс гранулярности: реальность — «требования различаются по программам»,
  -- но курировать пер-программно 300 вузов соло невозможно. Требования привязаны к
  -- (university, degree_level) как дефолт + опциональный program_id для исключений.
  -- UI: «типично для бакалавриата; отдельные программы могут отличаться» + ссылка наружу.
  id, university_id FK, program_id FK NULL, degree_level degree_level,
  sat_min, sat_p25, sat_p75,           -- диапазоны из Scorecard, где есть
  sat_required TEXT,                   -- 'required' | 'optional' | 'not_used'
  ielts_min NUMERIC(2,1), toefl_ibt_min, gpa_min,
  extracurriculars_weight TEXT,        -- 'none' | 'considered' | 'important'
  notes_ru TEXT, extra JSONB,          -- нюансы + страновое: {"ent_accepted": true, "topik_level": 3}
  data_source, source_url, last_verified_at,
  UNIQUE (university_id, degree_level, program_id)
)
costs (
  id, university_id FK, degree_level degree_level,
  cost_type TEXT,                      -- 'tuition_year' | 'application_fee' | 'living_estimate_year'
  amount NUMERIC(12,2), currency CHAR(3),   -- ОРИГИНАЛЬНАЯ валюта, всегда
  amount_usd NUMERIC(12,2),            -- денормализовано при импорте, пересчёт при обновлении курса
  academic_year TEXT,                  -- '2026/27'
  data_source, source_url, last_verified_at,
  UNIQUE (university_id, degree_level, cost_type)
)
deadlines (
  id, university_id FK, degree_level degree_level,
  round_name TEXT,                     -- 'Early Action' | 'Regular' | 'Fall intake'
  deadline_date DATE, intake_term,     -- 'Fall 2027'
  data_source, source_url, last_verified_at
)
profiles ( user_id UUID PK REFERENCES auth.users,   -- auth.users ведёт Supabase
  sat_score, ielts_score, toefl_score, gpa, budget_usd_year, target_degree, created_at )
favorites ( user_id FK, university_id FK, created_at,
  PRIMARY KEY (user_id, university_id) )
outbound_clicks (   -- метрика монетизации с 1-го дня, храним у себя
  id, university_id FK, user_id UUID NULL, target_url, clicked_at )
currency_rates ( currency CHAR(3) PK, usd_per_unit, fetched_at )  -- еженедельно (open.er-api.com)
```

- В `universities` добавить: `aliases TEXT[]` (русские написания: «Гарвард», «каист» — рукописные алиасы для 300 вузов бьют любой поисковый движок), `external_ids JSONB` (ключ upsert'а для Scorecard и др.), `search_vector tsvector GENERATED` по name_en+name_ru+city.
- **Мультивалютность:** фильтр по бюджету — по `amount_usd`, показ — оригинал + ≈USD + ≈KZT с датой курса (тенге волатилен).
- Баллы в `profiles` = «заполнил один раз — фильтруешь всегда», крючок удержания.
- Индексы: GIN по `search_vector`, GIN trigram по `name_en`, `costs(cost_type, amount_usd)`, `admission_requirements(degree_level, sat_min, ielts_min)`, `deadlines(deadline_date)`.
- RLS на `favorites`/`profiles` как defense-in-depth, хотя доступ идёт через FastAPI.

## 5. Пайплайн данных (поэтапно — это и есть продукт)

Скрипты в `pipeline/`, сначала запуск руками, потом **cron через GitHub Actions** (бесплатно; заодно keep-alive для Supabase). Каждый импортёр пишет `data_source`, `source_url`, `last_verified_at`.

- **Фаза A — сид (нед. 1–2):** `seed_hipolabs.py` — имена/страны/домены ~300 целевых вузов (`is_published=false` — это скелет, не публикуемые данные); `import_scorecard.py` — обогащение американских (SAT p25/p75, acceptance rate, tuition; upsert по `external_ids`); UK — CSV Discover Uni (CC-BY — **атрибуция в футере обязательна**); `update_fx.py` — еженедельные курсы валют + пересчёт `amount_usd`.
- **Фаза B — ручная курация (нед. 2–8 и навсегда):** один мастер Google Sheet, вкладки зеркалят таблицы, дропдауны-валидация для enum'ов → `import_sheet.py` (CSV-export URL без auth — проще Sheets API; валидация каждой строки Pydantic'ом — новичок здесь по-настоящему выучит валидацию; невалидные строки отклоняются громко, никогда молча; diff-отчёт; upsert). Workflow: открыл официальную страницу international admissions → заполнил строку → `last_verified_at = today` + `source_url`. Один вуз ≈ 20–30 мин; 100 вузов ≈ 40–50 часов — реалистично за 4–6 недель параллельно с учёбой. Норма: 20 вузов/нед фиксированными батчами; привлечь 2–3 друзей-кураторов (колонка `curated_by`). **Админка = table editor Supabase** для быстрых правок; Sheet — источник истины (импортёр выигрывает конфликты). Кастомную админ-UI в v1 НЕ строить. Написать `docs/curation_guide_ru.md` — пригодится волонтёрам.
- **Фаза C — парсеры (фаза 2+, осторожно):** только сайты, чьи ToS/robots.txt позволяют; жёсткий rate-limit (1 req/2 сек); парсить факты (дедлайны, сборы — факты не защищены копирайтом), не тексты; **никогда не парсить QS/THE/UniPage/Studyportals**; парсеры пишут *предложения* в очередь на ревью (таблица `staging_changes`), никогда напрямую в опубликованные строки. При 300 вузах ручная курация дешевле поддержки парсеров.
- **Свежесть в продукте:** на каждой детальной странице «Проверено: 12.07.2026 · Источник: официальный сайт» со ссылкой; еженедельный `freshness_report.py` — строки старше 120 дней = to-do курации. Честно-устаревшее лучше скрыто-устаревшего; сама прозрачность — дифференциатор против агентств.

## 6. API (REST, `/api/v1`)

```
GET  /universities                     # поиск с фильтрами, пагинация
     ?q=строка                         # FTS + trigram по именам/городу/алиасам
     &country=US,KR&degree_level=bachelor
     &max_tuition_usd=30000&max_app_fee_usd=100
     &sat=1350&ielts=7.0               # eligibility: sat >= sat_min и т.п.
     &deadline_after=2026-10-01
     &sort=tuition_asc|deadline_asc|name&page=1
GET  /universities/{slug}              # детальная: требования по уровням, стоимость, дедлайны,
                                       # last_verified_at + источник на каждый блок
GET  /meta/filters                     # страны, min/max tuition, уровни — питает UI фильтров
GET  /me/profile    PUT /me/profile    # баллы, бюджет (Bearer JWT от Supabase)
GET  /me/favorites  POST /me/favorites  DELETE /me/favorites/{id}
POST /events/outbound-click            # fire-and-forget beacon → таблица outbound_clicks
POST /admin/import                     # триггер импорта из Sheet (по админ-ключу)
GET  /health
```

- Eligibility-фильтрация в v1 — обычные SQL WHERE, без ML и «шансов». Вуз с `sat_min IS NULL` проходит фильтр, но получает бейдж «требования уточняйте на сайте», а не скрывается.
- Эндпоинтов `/auth/*` нет — фронт общается с Supabase напрямую, бэкенд только проверяет JWT. CORS замкнут на домен Vercel.
- Избранное до логина — в localStorage; при первом логине мёрдж в БД (один эндпоинт, ~20 строк).

## 7. Поиск: Postgres FTS + pg_trgm, НЕ Elasticsearch

При 300–3000 вузах весь датасет в shared_buffers, trigram-поиск по ~600 строкам имён — <5 мс. pg_trgm решает реальную проблему (нечёткий матч «Гарвард»/«Harvard»/«Havard»), `name_ru` рядом с `name_en` даёт двуязычный поиск. Структурные фильтры (страна, SAT ≤ X, бюджет ≤ Y) — обычные индексированные WHERE. Elasticsearch = второй stateful-сервис без бесплатного тарифа + баги синхронизации индекса, ради нуля пользы ниже ~100k документов.

## 8. Фазы MVP и порядок работ

- **Нед. 1–2:** монорепо (`/frontend`, `/backend`, `/pipeline`, `/docs`), схема + Alembic, сид-скрипты, hello-world задеплоен end-to-end (Vercel + Render + Supabase). **Деплой первым делом, не последним** — сюрпризы free tier дешевле всего обнаружить рано; публичный URL к неделе 2 = мотивация.
- **Нед. 3–4:** эндпоинт поиска/фильтров + страница каталога + детальная страница (русский UI), pg_trgm-поиск, шаблон Google Sheet + импорт; старт курации 20 вузов/нед; избранное в localStorage.
- **Нед. 5–6:** Supabase Auth + серверное избранное (мёрдж localStorage при первом логине), профиль (баллы/бюджет) → предзаполнение фильтра «мои шансы». Избранное — единственная фича за логином, намеренно (меряет реальный интент).
- **Нед. 7–8:** докурировать до 100 вузов (примерно: США 40 / UK 15 / ЕС 10 / Корея+Япония+Китай 20 / Турция 15 — по казахстанскому спросу), бейджи «проверено N дней назад», аналитика, полировка; **софт-запуск на одноклассниках братишки → казахстанские студенческие Telegram-чаты**.
- **Фаза 2 (мес. 3–5):** калькулятор шансов — rule-based светофор зелёный/жёлтый/красный против диапазона SAT p25–p75 (прозрачно и объяснимо, никакого ML); сравнение 2–4 вузов бок о бок (клиентское, поверх существующего API); email-напоминания о дедлайнах для избранного (GitHub Actions cron + Resend free, 100 писем/день); казахский язык; SEO (пререндер детальных страниц); рост до 300 вузов.
- **Фаза 3 (мес. 6+):** трекер заявок (статусы, чеклисты по вузам), отзывы поступивших казахстанцев (защищаемый контент-moat), монетизация: лид-ген для IELTS/SAT-центров Алматы/Астаны, спонсорские профили, freemium. Только здесь оправдан бюджет >$0.

**Явно ВНЕ фазы 1:** наполнение таблицы programs, казахский/английский UI, сравнение, напоминания, кастомная админка, парсеры, SSR/SEO, мобильное приложение (никогда — responsive web).

## 9. Бизнес-аналитика с 1-го дня

События: `search_performed` (с фильтрами), `university_viewed`, `favorite_added`, **`apply_url_clicked`** (ключевая метрика ценности), воронка viewed → favorited → clicked_apply. КЗ-специфика для проверки гипотез: какие страны реально ищут (ставка: Корея/Турция недообслужены), какие реальные диапазоны SAT/IELTS вводят (калибрует, какие вузы курировать дальше), сезонность (окт–янв для США).

**Метрика успеха MVP:** 10 реальных абитуриентов из КЗ говорят «это сэкономило мне часы» — измеряется кликами на `apply_url` и избранным-за-сессию.

**Монетизация (последовательность, не в MVP):** лид-ген для местных IELTS/SAT-центров (самый быстрый первый доход, без конфликта интересов) → freemium (напоминания, трекер, ревью эссе; якорь цены: агентства берут 108k–1M KZT, премиум 15–30k KZT/год — дёшево на их фоне) → спонсорские профили вузов (модель Niche ~$10k/год) при заметном трафике из ЦА → опционально комиссия за зачисление (10–20% первого года — но это превращает в агентство, осторожно).

| Риск | Митигация |
|---|---|
